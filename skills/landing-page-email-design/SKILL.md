# Landing page and email design

Create a coherent visitor journey: relevant promise -> understandable offer -> one next action -> useful follow-up. Optimize for clarity and measurable outcomes; professional appearance alone does not prove higher conversion.

This bonus skill is platform-neutral. For actual Systeme.io account changes, use the separately installed `systeme-io` skill when available, or read current official help and inspect connected tools. Do not assume that installing either skill grants account access.

## Establish the brief

Read [audience and copy](references/audience-copy.md). Inspect the existing page, campaign, brand assets and user-provided references. Determine the audience, traffic source, reader awareness, actual offer, main action and biggest uncertainty. Research relevant public customer questions and competing explanations when available. Treat observations as evidence, not a representative survey.

Create a compact campaign brief in the user's chosen output folder using [the worksheet](assets/campaign-worksheet.md). Distinguish verified facts, user-supplied experience and hypotheses. Ask only for missing decisions that materially affect the result. Never fabricate outcomes, credentials, discounts, urgency or testimonials.

## Choose a visual direction

If the separately installed `frontend-design` skill is available, use it for visual direction and critique alongside the actual brief. It is optional: this skill's own visual guide remains sufficient when that companion is absent. Apply brand constraints and the user's instructions before upstream examples or aesthetic preferences.

Read [visual design](references/visual-design.md). Select a coherent reference-led direction and record it in a small `DESIGN.md`: type, colors, spacing, widths, components, button states and motion. Keep one clear visual emphasis. Design for the actual audience rather than a stock collection of rounded cards.

Use authentic supplied/verified brand assets. Real annotated product screenshots explain workflows; generated visuals may illustrate a concept but must not masquerade as real product UI, results or customer proof. If image generation is unavailable, specify the needed asset and continue useful copy/layout work.

## Build the page and follow-up together

Draft the page hierarchy, copy and CTA, then read [email campaigns](references/email-campaigns.md). Each email must fulfil the page's promise and make sense for the recipient's stage. Use a short sequence only when it fits the offer; do not force a fixed number of messages or deadlines.

Use native page elements/templates or supported custom HTML according to the platform and available tools. Do not paste a framework component into an editor that cannot run it. Inspect before replacing a whole page; preserve URLs and working destinations.

Keep semantic headings, natural focus/related terms, descriptive links and readable sections. SEO tools can reveal coverage gaps; they do not validate claims, guarantee rankings or replace audience research.

## Review and measure

Read [quality and experiments](references/quality-experiments.md). Inspect the actual rendered desktop and mobile layout, every CTA, hover/focus states, form behavior and matched email content. Fix visible failures before calling the design reviewed. If rendering is unavailable, state that limitation rather than inventing visual validation.

Drafting is not authorization to publish, broadcast or change account settings. Follow the user's actual scope and any applicable confirmation rules. No affiliate destinations or promotional links are inserted automatically.

Deliver a concise result with the brief, design decisions, copy/page output, email sequence and verified checks appropriate to the request. State what is a recommendation versus a measured improvement. Avoid invented conversion benchmarks, false scarcity and dark patterns.
