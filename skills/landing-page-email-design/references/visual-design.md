# Create an intentional visual system

## Reference and direction

Inspect the current design and one useful reference. Describe what to borrow as principles: hierarchy, rhythm, image placement or navigation, rather than copying a brand. Record the desired tone and one memorable feature before building. A professional coaching page, a technical product demo and a beginner course should not receive the same stock composition.

Define roles in `DESIGN.md`: heading/body type, text and background colors, primary/secondary action colors, spacing scale, content width, borders, radii, icon family and state behavior. Prefer an existing licensed font/system stack when a new font adds no value. Distinguish page-wide changes from local section changes.

## Layout decisions

- Give the hero a clear benefit, an appropriate visual and one primary action. Align adjacent content rather than forcing symmetry.
- Keep prose comfortably narrow. Use wider space for demonstrations, comparisons or diagrams only when useful.
- Separate sections with meaningful whitespace. Use fewer columns as the screen narrows; do not shrink text to preserve a desktop grid.
- Vary section forms by purpose: narrative explanation, step sequence, table, demo, FAQ or compact offer panel. Avoid repeating identical cards for every paragraph.
- Use one icon family, with different symbols for different meanings. Do not repeat a decorative wallet beside every plan heading. Keep decorative icons out of accessible names.
- Make pricing and savings easy to compare, with actual billing terms and consistent units. Calculate savings from verified figures; distinguish annual totals from monthly equivalents.
- Keep button text readable in default, hover, focus and active states. Add an icon only when it supports the action; avoid duplicate arrows or flashing decoration.

## Media and motion

Use meaningful product demonstrations or illustrations. Do not repeat the same cover as multiple inline images. Images need sensible dimensions, descriptive text alternatives and appropriate compression. Reserve space for videos; give the reader enough context before a relevant demo, then a contextual next step.

Use subtle motion to explain interaction or hierarchy. Respect reduced-motion settings. Avoid scroll hijacking, large decorative scripts and effects that obscure text. If a library is unsupported by the platform, use a simpler supported treatment.

## Accessibility

Use real nested headings and labeled forms. Standard text should meet 4.5:1 contrast and qualifying large text 3:1. Check keyboard navigation, focus visibility and whether zoom/reflow remains usable. A contrast check alone does not establish complete accessibility compliance.

Primary references: [W3C headings](https://www.w3.org/WAI/tutorials/page-structure/headings/), [W3C contrast guidance](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).
