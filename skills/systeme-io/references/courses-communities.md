# Courses, enrolments and communities

Clarify whether the user is creating their own course, managing students or enrolling in official training. These are different tasks. Do not confuse the general platform certification with Funnel Builder certification, or promise a certificate for a course that does not issue one.

For owned courses, map modules, lessons, assets, access policy, offer and delivery before building. Inspect the existing course and plan allowance. Use current help for full/drip/partial access and the builder's exact meaning of each setting. Do not invent lesson counts, current student capacities or completion times.

Official tools may create course content when exposed. Extra MCP manages access to existing courses. Inspect real course, contact and membership IDs. Preview grant/revoke operations; removing access is not a refund. Partial access needs the actual module identifiers supported by the schema.

For communities, distinguish membership from community creation and post moderation. Check current membership before adding to avoid duplicates. The companion cannot moderate posts.

Verify the saved structure/access record. Check the student experience with authorized access where available; do not claim a student view was tested from an admin screenshot alone.

For certification guidance, read the specific official enrolment page and current requirements. Videos are supporting context, not proof of current exam rules, certificate entitlement or employment outcomes.

Sources: [Course help](https://help.systeme.io/category/163-courses-member-sites), [Platform certification](https://systeme.io/certification), [Funnel Builder certification](https://systeme.io/funnel-builder-certification).
