# Account, domains and migration

## Prepare

Inspect plan and usage before proposing resources. Check the target language, currency, business purpose, domain ownership and whether the domain already serves a live asset. Do not replace a homepage or connected domain accidentally.

Search official sources for `connect domain`, `domain homepage`, `subdomain`, `CAA`, `account restrictions` or the migration provider. Record exact current dashboard DNS values; never reuse another account's records. Explain whether a change affects the whole domain or one subdomain. Keep existing email/DNS records unless the task calls for a specific change.

## Act

For a new site, select an available account domain or an authorized custom domain. If the custom domain is not owned or configured, separate that dependency from the page draft. DNS setup and email authentication are different jobs; completing one does not prove the other.

For migration, map source pages, URLs, contacts with consent, files, products and access rules before importing. Start with a small authorized sample, compare it, then continue. Avoid subscribing imported contacts to live campaigns as an implicit side effect.

## Verify

Check DNS resolution, HTTPS, dashboard domain status and public target page separately. Allow for propagation without calling an unapproved domain a completed connection. Preserve evidence of any redirects and homepage assignment.

Sources: [General help](https://help.systeme.io/category/131-general), [Migration help](https://help.systeme.io/category/2297-migrating-to-systemeio). Exact provider steps must be read from the indexed current article.
